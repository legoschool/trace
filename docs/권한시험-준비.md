# 🔬 100명 한도를 푸는 길 찾기 · 권한 시험 준비

> **20분이면 끝납니다.** 구글 계정 하나만 있으면 됩니다.
> 이 문서는 [SETUP.md](../SETUP.md) 와 같은 화면을 지나갑니다. 사진은 그쪽 것을 그대로 씁니다.

---

## 무엇을 알아보려는 건가

지금 기록장은 로그인할 때 **「드라이브 전체」** 권한을 달라고 합니다.
구글은 이걸 **가장 무거운 권한**으로 보고, 심사를 통과하기 전에는
**한 프로젝트당 평생 100명**만 로그인하게 막습니다.

권한을 **`drive.file`**(이 앱으로 만들거나 고른 것만) 로 낮추면
**심사도 한도도 없어집니다.** 그런데 그러면 이런 걱정이 생깁니다.

> **다른 데서 만들어 온 파일을 폴더에 넣고 「가져오기」·「이름 바꾸기」 하는 게 안 되는 것 아닌가?**

여기에 답이 하나 있습니다. 구글 Picker로 **폴더를 통째로 고르면**
그 안의 것들까지 권한이 따라올 수 있습니다. 따라오면 전부 그대로 삽니다.

그래서 두 가지를 눈으로 확인합니다.

| | 확인할 것 | 이게 되면 |
|---|---|---|
| **(가)** | 폴더를 고를 때 **이미 안에 있던** 파일이 보이는가 | 예전 기록을 계속 쓸 수 있다 |
| **(나)** | 폴더를 고른 **뒤에 손으로 넣은** 파일이 보이는가 | 「가져오기」가 지금처럼 작동한다 |

**(나)가 핵심입니다.**

---

## ⚠️ 왜 새 프로젝트를 만들어야 하나

지금 쓰는 프로젝트로 시험하면 **답이 나와도 믿을 수 없습니다.**

`drive.file` 권한은 「이 앱이 만든 파일」도 보여 줍니다.
그런데 지금 프로젝트의 앱은 이미 「드라이브 전체」 권한으로 **수많은 파일을 만들어 놨습니다.**
그러니 파일이 보여도 그게

- **폴더를 골라서** 보이는 건지 (← 우리가 알고 싶은 것)
- 원래 **앱이 만든 거라서** 보이는 건지

구분이 안 됩니다. **아무것도 만든 적 없는 새 프로젝트**여야 답이 깨끗합니다.

# 0부 · 시험용 폴더를 손으로 만듭니다

## 1. 드라이브에 폴더를 하나 만듭니다

[drive.google.com](https://drive.google.com) 에서 **`권한시험`** 같은 이름으로 새 폴더를 만듭니다.

> ⚠️ **기록장이 쓰던 폴더를 고르면 안 됩니다.** 앱이 만든 파일이 섞여 있어서 위와 같은 이유로 시험이 흐려집니다.

## 2. 그 안에 파일을 손으로 넣습니다

**기록장을 거치지 않고** 넣어야 합니다. 메모장으로 만들어 끌어다 놓거나, 아무 파일이나 올리면 됩니다.

- 텍스트 파일 두 개 — 예: `시험1.md`, `시험2.md` (안에 아무 글이나 몇 줄)
- 하위 폴더 하나 — 예: `안쪽`
- 그 하위 폴더 안에 파일 하나 — 예: `시험3.md`

하위 폴더까지 넣는 이유는, 기록장이 **10단계 깊이까지 훑기** 때문입니다.
한 겹만 보이고 그 아래는 안 보이면 그것도 알아야 합니다.

# 3부 · 로그인 화면 만들기

## 8. 왼쪽 메뉴에서 `Google 인증 플랫폼` 을 찾습니다

`API 및 서비스` → `OAuth 동의 화면` 자리입니다. 이름이 **`Google 인증 플랫폼`** 으로 바뀌었습니다.
주소창에 이걸 쳐도 곧장 갑니다.

```
https://console.cloud.google.com/auth/branding
```

> ⚠️ **새 프로젝트에서는 `브랜딩`·`대상`·`클라이언트` 메뉴가 아직 안 보입니다.**
> 대신 「구성되지 않았습니다」 안내와 **`시작하기`** 단추 하나만 있습니다. 그걸 누르면 짧은 마법사가 뜹니다.
>
> 1. **앱 정보** — 앱 이름 `권한시험`, 사용자 지원 이메일은 내 구글 주소
> 2. **대상** — `외부`
> 3. **연락처 정보** — 내 이메일
> 4. 동의에 체크하고 `만들기`
>
> 마법사를 끝내야 왼쪽에 `브랜딩` `대상` `클라이언트` `데이터 액세스` 가 생깁니다.
> **여기서 1·2번을 이미 채웠다면 아래 9번·10번은 끝난 것입니다.** 11번(테스트 사용자)으로 바로 가세요.

# 5부 · API 키와 프로젝트 번호

## 19. API 키 만들기 · ⚠️ 여긴 메뉴가 다릅니다

폴더 고르기 창(Picker)은 클라이언트 ID 말고 **API 키**를 따로 요구합니다.

> ⚠️ **API 키는 「Google 인증 플랫폼」 왼쪽 메뉴에 없습니다.**
> 거기를 나와 **`API 및 서비스` → `사용자 인증 정보`** 로 가야 합니다. 주소로 바로 가려면:
>
> ```
> https://console.cloud.google.com/apis/credentials
> ```

위쪽 **`+ 사용자 인증 정보 만들기`** → **`API 키`**.
`AIza...` 로 시작하는 값이 나오면 **복사해 둡니다.**

`API 키 만들기` 창이 뜨면 이렇게 채웁니다.

| 칸 | 할 일 |
|---|---|
| 이름 | 아무거나 |
| **`API 제한사항 선택`** ＊ | **`Google Picker API`** 체크 (Drive API 도 같이 체크해도 됨) |
| `서비스 계정을 통해 API 호출 인증` | **체크하지 않음** |
| `애플리케이션 제한사항` | **`없음`** 그대로 |

> ⚠️ **API를 하나도 안 고르면 「API를 선택해야 합니다」 가 뜨며 만들어지지 않습니다.**
> 그리고 드롭다운에는 **이 프로젝트에서 켜 둔 API만** 나옵니다.
> `Google Picker API` 가 안 보이면 7번(API 켜기)을 안 한 것이니 먼저 켜고 오세요.

## 20. **프로젝트 번호**를 적어 둡니다

콘솔 첫 화면(대시보드)의 `프로젝트 정보` 칸에 **프로젝트 번호**가 있습니다.
`000000000000` 같은 열두 자리 숫자입니다.

> 💡 **따로 찾을 것 없이 클라이언트 ID 앞부분의 숫자와 같은 값입니다.**
> `123456789012-abcd....apps.googleusercontent.com` 이라면 `123456789012` 입니다.
> Picker가 「이 앱에 폴더 권한을 넘긴다」고 표시할 때 이 번호를 씁니다.

> ⚠️ 클라이언트 화면에 함께 보이는 **`클라이언트 보안 비밀번호` 는 쓰지 않습니다.**
> 시험 페이지에도, 어디에도 붙여넣지 마세요. 브라우저에서 도는 앱이라 필요가 없습니다.

## 23. `0단계` 칸에 세 가지를 붙여넣고 `저장`

클라이언트 ID · API 키 · 프로젝트 번호.

## 24. 위에서 아래로 단추를 순서대로 누릅니다

| 단계 | 누를 것 | 나와야 맞는 것 |
|---|---|---|
| 1 | 구글 로그인 | 동의 화면에 **「드라이브 전체」가 아닌** 좁은 문구 |
| 2 | 맨 위 훑어보기 | **0개** (권한이 좁다는 증거) |
| 3 | 폴더 고르기 | 0부에서 만든 `권한시험` 폴더를 고름 |
| 4 | 훑어보기 | 손으로 넣은 파일들이 보이면 **(가) 통과** |
| 5 | 본문 읽기 / 이름 바꾸기 | 둘 다 성공 |

> ⚠️ 2단계에서 파일이 잔뜩 나오면 **옛 프로젝트를 쓰고 있는 것**입니다. 5번으로 돌아가세요.

## 25. ⭐ 6단계 · 여기가 진짜 시험입니다

**시험 페이지를 켜 둔 채** 다른 탭에서 드라이브를 엽니다.
`권한시험` 폴더 안에 파일을 **하나 손으로 새로 넣습니다.** 예: `나중에넣음.md`

넣은 다음 시험 페이지로 돌아와 **`다시 훑어보기`**.

- 방금 넣은 파일이 목록에 **보이면 → (나) 통과**
- **안 보이면 → (나) 실패**

## 26. `결과 요약 복사` 를 눌러 붙여 주세요
