drive.file 권한 시험

좁은 권한(drive.file)만 받은 상태에서, 구글 Picker로 폴더를 고르면 내가 손으로 넣어 둔 파일까지 앱이 볼 수 있는지 확인합니다. 이 답에 따라 100명 한도를 푸는 길이 갈립니다.

0준비

구글 클라우드 콘솔에서 가져와 붙여 넣습니다. 이 브라우저에만 저장되고 어디로도 보내지 않습니다.

깨끗한 시험을 위해 새 프로젝트를 하나 만드시길 권합니다. 기존 프로젝트를 쓰면, 앱이 예전에 「드라이브 전체」 권한으로 만들어 둔 파일이 섞여 「폴더를 골라서 보이는 것」과 「원래 앱이 만든 것이라 보이는 것」이 구분되지 않습니다.

새 프로젝트에서 ① OAuth 클라이언트 ID(웹) 만들고 승인된 JavaScript 원본에 http://localhost:8000 넣기 ② API 및 서비스에서 Google Drive API 와 Google Picker API 사용 설정 ③ API 키 만들기 ④ 프로젝트 번호는 콘솔 첫 화면에 있습니다. ⑤ 대상(동의 화면)은 「외부」, 테스트 사용자에 내 구글 주소 넣기.

👉 사진과 함께 하나씩 짚은 준비 문서 를 따라 하시면 20분입니다.
⚠️ 이 페이지는 반드시 http://localhost:8000/drivefile-test.html 로 열어야 합니다. 127.0.0.1 로 열면 구글이 다른 곳으로 보아 로그인이 막힙니다.

1로그인 · drive.file 만 요청

동의 화면에 「드라이브 전체」가 아니라 「이 앱으로 열거나 만든 파일」 같은 좁은 문구가 나와야 맞습니다.

아직 로그인하지 않았습니다.

2대조 확인 · 권한이 정말 좁아졌나

내 드라이브 맨 위를 훑습니다. 여기서 파일이 잔뜩 나오면 아직 넓은 권한이라 시험이 무의미합니다.

아직 하지 않았습니다.

3Picker로 폴더 고르기

앱이 만든 적 없는 폴더를 고르세요. 시험 전에 드라이브에서 손으로 폴더를 하나 만들고, 그 안에 .md나 텍스트 파일 두어 개, 하위 폴더 하나와 그 안의 파일 하나를 손으로 넣어 두면 가장 정확합니다.

아직 고르지 않았습니다.

3b폴더 ID 로 바로 잡기 · 「기존 기록이 살아남나」 시험용

Picker 를 거치지 않고 폴더를 지정합니다. 이미 쓰던 기록장 폴더가 그대로 보이는지 확인할 때 씁니다. 드라이브에서 그 폴더를 열면 주소 끝에 붙는 긴 글자가 폴더 ID 입니다.
drive.google.com/drive/folders/1AbC...여기

아직 하지 않았습니다.
기존 기록이 살아남는지 보는 순서
① 0단계 클라이언트 ID 를 실제 기록장 것으로 바꾸고 저장 (그 클라이언트의 「승인된 JavaScript 원본」에 http://localhost:8000 을 미리 넣어 두세요)
② 1단계 로그인 — drive.file 만 요청됩니다
③ 여기에 기존 기록 폴더 ID 를 넣고 이 폴더로 잡기
④ 4단계 훑어보기 — 그동안 쌓인 기록이 보이면 이주가 필요 없습니다

⚠️ 이 시험은 기존 앱에 아무 영향이 없습니다. 권한은 더해질 뿐 줄지 않고, 기록장 본체는 여전히 넓은 권한으로 돕니다.

4훑기 · 판정 (가)

고른 폴더 아래를 3단계까지 훑습니다. 손으로 넣어 둔 파일이 여기 나오면 (가) 통과입니다.

아직 훑지 않았습니다.

4b정밀 진단 · 어디까지 되는가

4단계에서 0개가 나왔다면 여기를 눌러 주세요. 폴더 자체는 잡혔는지, 그 안에 새로 만드는 것은 되는지를 갈라서 봅니다. 둘의 대응이 서로 다릅니다.
시험용으로 만든 파일은 확인이 끝나면 지웁니다.

아직 하지 않았습니다.

5본문 읽기 · 이름 바꾸기

「폴더에서 가져오기」는 본문을 읽어야 하고, 「이름 바꾸기」는 이름을 고쳐야 합니다. 둘 다 되는지 봅니다. 이름은 잠깐 바꿨다가 곧바로 되돌립니다.

아직 하지 않았습니다.

6다시 훑기 · 판정 (나) · 가장 중요

지금 드라이브를 열어 고른 폴더 안에 파일을 하나 손으로 새로 넣으세요. 이 페이지는 그대로 두고 다른 탭에서 하시면 됩니다. 넣은 뒤에 아래 단추를 누릅니다. 새로 넣은 그 파일이 목록에 나오면 (나) 통과입니다.

아직 하지 않았습니다.
